## 3.3 `error` signal 被多处覆盖 ★★

**文件**: `learning_notes_view_model.dart`

- `_loadNotes()` 内部 catch 写入 `error.value = '加载笔记失败: $e'`
- `refresh()` 的 catch 写入 `error.value = '加载失败: $e'`
- `initialize()` 的 catch 写入 `error.value = '初始化失败: $e'`
- `_loadBookTitles()` 和 `_loadNoteCount()` 不碰 `error`

三条独立路径写同一个信号，`_loadAll` 中三个方法并行运行，错误来源不可区分。如果 `_loadBookTitles` 失败（只设置 `bookTitles.state = error`）而 `_loadNotes` 成功，`error` 信号保持 null，用户看不到标题加载失败。

### 3.4 `_loadNotes` 的 `noteLoading` 未参与 refresh 的重试交互 ★★

**文件**: `learning_notes_view_model.dart:82-101`

`_loadNotes` 有自己的 `noteLoading`，而 `refresh` 有独立的 `loading`。两者有重叠：

- 首次 `initialize()` → `_loadNotes` 设置/清除 `noteLoading`，`initialize` 不碰 `loading`
- `refresh()` → 设置 `loading=true`，同时 `_loadNotes` 设置 `noteLoading=true`

Page 的 loading 判断是 `loading && noteList.value?.isEmpty`，所以首次加载显示 `CircularProgressIndicator`，refresh 时显示已有内容。这种设计合理，但 `loading` 和 `noteLoading` 的关系隐晦。

### 3.6 StatDashboard 不反映筛选后的笔记数 ▼

**文件**: `learning_notes_page.dart:60`

```dart
LearningNotesStatDashboard(noteTotalCount: noteTotalCount.value ?? 0),
```

`noteTotalCount` 是全局笔记总数，filter 后不变。如果用户筛选 "Book A"，dashboard 显示 "42 笔记" 但列表只有 5 条。这可能是预期设计（总数 vs 过滤后数目），但无区分。

### 3.8 `NoteItemCard` 的 border 写法可简化 ▼

**文件**: `note_item_card.dart:27-44`

```dart
border: Border(
  left: BorderSide(color: cs.primary, width: 3),
  right: BorderSide(color: ..., width: 0.5),
  top: BorderSide(color: ..., width: 0.5),
  bottom: BorderSide(color: ..., width: 0.5),
),
```

三条边相同，仅左边不同。可用 `Border.all` + left 覆盖：

```dart
decoration: BoxDecoration(
  color: cs.surface,
  borderRadius: BorderRadius.circular(12),
  border: Border.all(color: cs.outlineVariant.withValues(alpha: 0.2), width: 0.5)
    .copyWith(left: BorderSide(color: cs.primary, width: 3)),
),
```

### 3.9 `GoReadingEmptyState` 导航路径硬编码 ▼

**文件**: `go_reading_empty_state.dart:58`

```dart
onPressed: () => context.push(RoutePaths.bookshelf),
```

这是共享组件，路径在组件内部硬编码而非由调用方传入。如果将来笔记的空态导航到不同页面（如阅读引导），需修改此组件或增加参数。
