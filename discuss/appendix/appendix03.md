针对**离线阅读器**且为**中小型项目**的定位，核心约束是：**资源有限（内存/CPU）、开发人力有限、但用户体验要求高（流畅、秒开）**。

在 FRB 架构下，我为你总结了一份**“高性价比”**的取舍方案。我们的原则是：**重逻辑在 Rust，轻传输过 FRB，懒执行保体验。**

### 1. 核心策略总表

| 加载策略 | 推荐程度 | 在 FRB 中的角色 | 取舍理由 (针对中小型离线项目) |
| :--- | :--- | :--- | :--- |
| **分块加载 (Chunking)** | ⭐⭐⭐⭐⭐ | **基础架构** | **必选**。将书拆分为章/节，避免大文件撑爆内存。Rust 处理分块，Flutter 只请求当前块。 |
| **懒加载 (Lazy Loading)** | ⭐⭐⭐⭐⭐ | **性能核心** | **必选**。图片解码、复杂分页计算只在需要时执行。极大降低首屏延迟和内存峰值。 |
| **预取加载 (Prefetching)** | ⭐⭐⭐⭐ | **体验优化** | **强烈推荐**。利用 Rust 后台线程预算下一章。离线环境下无网络开销，纯 CPU 换体验，性价比极高。 |
| **流式加载 (Streaming)** | ⭐⭐⭐ | **特定场景** | **按需使用**。仅针对超大 TXT (>100MB) 解析时使用。普通 EPUB 直接解压到临时目录更高效。 |
| **零拷贝 (Zero-Copy)** | ⭐⭐ | **高级优化** | **暂不推荐**。FRB 目前对共享内存支持尚在演进，实现难度大。对于中小型项目，路径传递已足够快。 |

### 2. 详细取舍分析

#### **A. 为什么“分块”是基石？**
*   **取舍**：牺牲一点索引建立的复杂度，换取内存的绝对安全。
*   **FRB 实践**：
    *   Rust 层将整本书解析为 `Vec<Chapter>` 并存入 `sled`。
    *   Flutter 层永远不知道整本书有多大，它只知道“当前章有 50 页”。
    *   **优势**：即使是一本 1GB 的小说，App 启动时也只占用几 MB 内存加载元数据。

#### **B. 为什么“懒加载”是灵魂？**
*   **取舍**：牺牲首次翻页可能出现的微小等待（可通过预取消除），换取极低的初始负载。
*   **FRB 实践**：
    *   **图片**：Flutter 渲染到图片 Widget 时，才调用 Rust 的 `get_image_path`。Rust 此时才去解压、缩放、存盘。
    *   **分页**：用户不翻到的页，Rust 绝不计算其布局。
    *   **优势**：用户打开书的速度取决于“解析元数据”的速度，而不是“处理全书图片”的速度。

#### **C. 为什么“预取”是离线阅读器的杀手锏？**
*   **取舍**：牺牲少量的后台 CPU 和电量，换取“丝滑翻页”。
*   **FRB 实践**：
    *   当用户在读第 N 章时，Rust 启动一个 `tokio::spawn` 任务，静默计算第 N+1 章的分页索引，并预处理其中的前 3 张图片。
    *   **优势**：离线环境下，没有网络延迟，CPU 是唯一瓶颈。提前计算好，翻页就是纯粹的 UI 切换，没有任何卡顿。

#### **D. 为什么“流式”和“零拷贝”可以放一放？**
*   **流式**：除非你专门做“网文 TXT 阅读器”，否则 EPUB 的分块解析已经解决了大部分 I/O 问题。引入流式解析会增加 Rust 代码的复杂性（状态机管理）。
*   **零拷贝**：在中小型项目中，通过 `sled` 存文件路径，让 Flutter 自己 `Image.file()` 加载，性能损失通常在 5-10% 以内，但开发成本降低 80%。

### 3. 给你的 FRB 架构建议路线图

#### **第一阶段：MVP (最小可行性产品)**
1.  **分块**：Rust 解析 EPUB/TXT，按章存入 `sled`。
2.  **懒加载**：Flutter 请求哪页，Rust 就算哪页的分页索引。
3.  **简单缓存**：图片处理后存磁盘，Rust 返回路径。
*   **目标**：能看书，不崩溃，内存稳定。

#### **第二阶段：体验优化 (推荐优先做)**
1.  **预取**：在 Rust 层增加后台预取队列。
2.  **Config Hash**：实现字体/字号改变时的自动缓存失效。
3.  **信号同步**：用 `signals_flutter` 优化 UI 响应速度。
*   **目标**：翻页丝滑，改字体秒生效。

#### **第三阶段：极致性能 (如果有余力)**
1.  **自适应图片**：根据屏幕 DPI 动态调整图片缩放比例。
2.  **虚拟列表**：如果一章超过 100 页，优化 Flutter 侧的 Widget 复用。
*   **目标**：处理极端情况（如超大章节、高清图集）。

### 4. 总结一句话

对于你的离线 FRB 阅读器：
**用“分块”管内存，用“懒加载”管启动速度，用“预取”管翻页流畅度。**

忘掉复杂的流式和零拷贝，把精力花在 **Rust 的分页算法效率** 和 **Sled 缓存命中率** 上，这才是中小型项目产出比最高的地方。
