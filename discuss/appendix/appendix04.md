### 2. 潜在的风险点与应对建议

虽然计划很好，但在执行 Phase 1 时，有几个“坑”需要提前填平：

#### **风险 A：EPUB 纯文本提取的“语义丢失”**

*   **问题**：EPUB 是 HTML，直接转文本可能会丢掉段落间距。如果 `plainText` 里全是挤在一起的字，`charOffset` 虽然能定位，但用户视觉上会觉得排版乱了。
*   **建议**：在 Rust 解析器中，建立一个简单的**映射规则**：遇到 `<p>`, `<div>`, `<h1>` 等块级标签时，在 `plainText` 中插入 `\n\n` 或特定占位符。确保 `plainText` 的逻辑分段与视觉分段大致对齐。

#### **风险 B：PageTurn 动画与分页数据的解耦**

*   **问题**：现有的 PageTurn 可能强依赖某些旧的布局数据。
*   **建议**：在 Phase 1 开始时，先写一个**适配器（Adapter）**。让 PageTurn 动画层只关心“给我第 N 页的 Widget”，而不关心这页是怎么算出来的。这样后续切换到 IR 分页时，动画层可以零修改复用。

#### **风险 C：Orchestrator 的状态竞态**

*   **问题**：当用户快速翻页时，旧的 `contentFuture` 可能还没取消，新的请求就来了，导致状态错乱。
*   **建议**：在 Rust 侧实现一个简单的**任务取消机制**（例如使用 `tokio::select!` 或检查 `CancellationToken`）。如果新请求到来，旧的计算任务应立即终止，释放资源。

### 3. 给 Phase 1 的“加分项”建议

如果你在执行过程中有余力，可以考虑加入这两个小优化，它们能为 Phase 2 铺平道路：

1.  **预定义 `ContentBlock` 的 Rust 结构体**：
    虽然 Phase 1 不用它做分页，但可以先把 `enum ContentBlock { Text(...), Image(...) }` 定义好并导出到 Dart。这样在 Phase 2 切换时，Flutter 层的类型引用已经是现成的了。
2.  **增加“分页模式”的埋点/日志**：
    记录用户在分页模式下遇到的错误（如图片加载失败、分页索引缺失）。这些数据将帮助你在 Phase 2 优化块分页算法。
